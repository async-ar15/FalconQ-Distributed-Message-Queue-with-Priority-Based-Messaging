A cloud-native, high-performance distributed message broker engineered from first principles in Go. Designed for microservices that demand strict priority-aware delivery and zero data loss.

Explore Architecture

Why FalconQ?

Modern distributed systems face a critical challenge: head-of-line blocking. When bulk data processing competes with latency-sensitive control messages, traditional FIFO queues struggle. FalconQ introduces a native dual-queue architecture that prioritizes urgent messages at the storage level, combined with Raft-based consensus for enterprise-grade durability.

⚡ Strict Priority

Built-in dual queues guarantee that high-priority control messages bypass low-priority bulk messages instantly.

🛡️ Zero Data Loss

Powered by BadgerDB (LSM-tree), messages are durably appended to disk and replicated across a quorum before acknowledgment.

🔄 Distributed Consensus

Utilizes HashiCorp's robust Raft implementation for automated leader election and partition-level replication.

🚀 High Throughput

Designed to sustain over 1.5M messages/minute through horizontal partition scaling (Consistent Hashing) and batch consumption.

Quick Start

Get a local FalconQ cluster up and running in seconds.

# 1. Clone the repository
git clone https://github.com/async-ar15/FalconQ-distributed-message-queue.git
cd FalconQ-distributed-message-queue

# 2. Install dependencies
go mod tidy

# 3. Start a 3-node cluster (in separate terminals)
go run broker/main.go -config broker/config1.yaml -nodeid broker1
go run broker/main.go -config broker/config2.yaml -nodeid broker2
go run broker/main.go -config broker/config3.yaml -nodeid broker3

Once the cluster forms a Raft quorum and elects a leader, you can start publishing and consuming via the REST API.
