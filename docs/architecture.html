High-Level Cluster Topology

FalconQ brokers form a distributed cluster communicating over a robust networking layer. Each node acts as a publisher, consumer interface, and Raft peer.

Internal Topic & Partition Engine

A Topic in FalconQ is dynamically sharded into Partitions using Consistent Hashing. This allows the system to scale horizontally by spreading the storage and replication load across multiple broker nodes.

Crucially, every Partition contains two distinct queues: a High-Priority Queue and a Low-Priority Queue. When fetching messages, the broker completely drains the high-priority queue before touching the low-priority one, ensuring immediate processing of urgent events.

Consensus & Durability

FalconQ uses HashiCorp's Raft implementation to manage leader election and log replication per partition. When a client publishes a message to a partition, the request is forwarded to that partition's Leader.

The Leader appends the message to its local log and replicates it to Follower nodes. Acknowledgment is only sent back to the client once a quorum (majority) of nodes have safely persisted the message to their local BadgerDB stores, guaranteeing zero data loss.
